# v1.7 配置与部署

本分支是已有 WTC 安装的表格模式升级代码。它依赖旧项目的安装者标记和后台状态，没有全新空白项目的安装向导。公开代码不包含生产绑定或实际库存；提交 GitHub 不会自动升级线上脚本。

## 1. 本地验证与构建

需要 Node.js 和 Python 3。测试使用 Node 内置模块，构建仅使用 Python 标准库，不需要安装 npm 依赖。

在仓库根目录运行：

```bash
node --test nj_load_sync/*.test.js
python3 scripts/build_v1_7.py
```

构建脚本会先执行测试，再按固定模块顺序生成 `dist/WTC_LoadSync.gs` 和 `dist/release-manifest.json`。测试失败时不生成新的构建文件；测试日志保存在被 Git 忽略的 `dist/test-results.txt`。

也可以用 `WTC_NODE_BINARY` 指定 Node 可执行文件。构建过程不会读取外部临时目录、生产备份或在线表格。

## 2. 配置目标项目

在 Google Apps Script 的“项目设置 → 脚本属性”中，手动添加以下配置。`config/script-properties.example.json` 仅说明属性名称，不会自动导入。

| 属性 | 内容 |
| --- | --- |
| `WTC_MAIN_SPREADSHEET_ID` | 综合业务表的文件 ID，不填写完整网址 |
| `WTC_UNLOAD_SPREADSHEET_ID` | 拆柜地图所在文件的 ID |
| `WTC_LOCATION_SHEET_ID` | 手动维护的「库位表」页签的数字 gid；0 也是有效值 |

请保留已有安装身份与后台属性，不要复制其他人的安装者标记、密钥或状态。缺少必要配置时，公开版拒绝继续读取和提交，不会回退到原仓库绑定。

以下仍是业务适配项，不能只替换三个 ID 就假定适用于任意仓库：

- 「库位表」页名与分区矩阵布局。
- 「NJ装车接龙」的表头及列映射。
- 日、周、月预报格式、来源配置与柜号对应规则。
- 拆柜地图日期页、可见页筛选及表头布局。
- `America/New_York` 业务时区、容量和禁用库位规则。G10/G11 的限制属于原仓业务规则，需要迁移者自行核对。

安装账号须能读取来源文件、写入独立结果页，并使用项目所需的 Google Sheets API 和触发器权限。新表格模式不需要 OpenAI API Key。

## 3. 升级已有安装

1. 用原安装账号运行 `WTCLoad_pauseForMaintenance`，确认旧的在途执行已结束。
2. 私下备份现有代码与必要状态；不要将备份提交到公开仓库。
3. 配置上述脚本属性，完整替换该项目中的 WTC 同步脚本，保留无关脚本。
4. 保存并运行 `WTCLoad_upgradeProjectV17`。升级建立独立表格比较基准，保留业务原表和旧账，阻止旧入账入口。
5. 打开综合表中的“库位同步 → 打开库位工作台”，检查来源、未知数量和读取问题。
6. 运行 `WTCLoad_resumeAfterMaintenance`，再运行 `WTCLoad_syncTableInventory`。
7. 核对成功回执、版本 `1.7.0`、新读取时间，并确认后台 `WTCLoad_tick` 成功执行。

脚本编辑器环境可能无法刷新菜单；此时重新打开或刷新综合表。缺少有效表格 UI 环境时，不能仅凭菜单刷新结果判断数据是否读取成功，应检查实际执行回执。

## 4. 验收边界

- 当前数量来自指定库位表；未知数量不能用旧账补齐。
- 未修改来源表时，重复读取不新增库存变化记录。
- 拆柜与装车状态、预报只进入辅助结果，不再次增减实存。
- 真实收工必须由人员核对后明确点击保存；不要为验证功能虚构生产收工记录。
- 读取失败时保留上次有效结果，并显示失败或历史数据时效。

升级失败后保持暂停并排查原因，不应关闭表格模式开关后重跑旧队列，以免重复记账。

## 旧版兼容配置

源码保留旧引擎用于兼容和回归测试。公开版不附带原仓库预置的卸柜任务；旧路径如确需使用，另需适配 `WTC_LEGACY_UNLOAD_SOURCE_TAB` 和 `WTC_LEGACY_UNLOAD_TASKS_JSON`。v1.7 表格模式不需要这两项旧任务配置，也不应为启用 v1.7 而重跑旧版安装或入账流程。
